On the stand an integration run overwrites the live abort thresholds. Fix belongs in WP4 (park and restore it like the others); the gate now fails on any dirty tracked file after a run.

**Lead REPORT.md with these (safety-relevant on the real stand), each with its operator-visible consequence:** H-1 (fixed), C2-2 (shipped profile TOMLs never checked for underscore ints), C6-3 (server-heartbeat loss undetected; daq_bridge never takes over), C6-4 (board shown disconnected while its data still displays), C6-1 (log claims SENSOR_CONFIG sent, 0 packets), C6-6 (config_broadcast silent unless an actuator board is designated survivor), C4-1 (sequencer deadlock: aborts fail after entering a refused dynamic state), C4-3 (abort does not cancel a pending stage: a valve can move after the abort batch), C1-9 (CLEAR_ABORT is never sent: boards are never told the abort is cleared), C3-3 (the backend picks its PT calibration file by mtime among 13 tracked files: after a git pull / checkout / rsync / deploy the GUI's calibration panel can report, and its save-coefficients command can write from, a different file — here one with no coefficients — with no config change. Live PT pressures are NOT affected: `calculatePressure` has no caller; live conversion is calibration_service's cubic store), C1-10 (each abort sends 8 ABORTs then 4 ABORT_DONEs: `triggerAbort` runs twice), C2-1 (digital-twin fire timer disabled), C2-4 (bad/missing TOML → service starts on defaults).

From C1 (packets/Elodin; each frozen in a golden):
- C1-1 `create_abort_done_packet` writes `version = 1`; every other encoder writes 0.
- C1-2 config_broadcast writes abort IPs in ACTUATOR_CONFIG reversed (d,c,b,a) via `memcpy` of `a<<24|…`; SENSOR_CONFIG `controller_ip` is a,b,c,d.
- C1-3 `create_sensor_data_packet`: `uint8_t` loop counter (>255 chunks loops forever) and `memcpy`s `num_sensors` datapoints regardless of the vector's size (over-read).
- C1-4 `parse_sensor_config_packet` / `parse_actuator_config_packet` write partial outputs before failing.
- C1-5 Parsers ignore the version byte and accept trailing bytes (the pipeline enforces both only for ENVIRONMENTAL_DATA).
- C1-6 TS `ElodinClient` never resyncs on an implausible length: waits forever, buffers, re-schedules `setImmediate` every tick.
- C1-9 CLEAR_ABORT is never sent: nothing calls `AbortBroadcaster::sendClearAbort`.
- C1-10 The sequencer calls `triggerAbort` twice per abort transition: each abort sends 8 ABORTs (2 × 4 repeats), then 4 ABORT_DONEs. The second call joins the first's ABORT_DONE thread, which waits out a 50 ms step: the abort state is published to Elodin/the GUI 37–79 ms after the valves are commanded (non-abort entries 3–17 ms) (D50).
- C1-11 In the default profile `[stacklight_service] elodin_port` overrides the `--elodin-port` CLI flag (stacklight connects to 2240 regardless).
- C1-12 daq_bridge ignores its `bind_port` argument (argv[3]) when the config has `[network] sensor_port`.
- C1-8 A malformed board IP in config (`not-an-ip`) is encoded as 0x00000000 — a typo'd IP silently becomes 0.0.0.0 on the wire (config_broadcast `ipToU32Le`).
- C1-7 With config_base's cubic models and no thresholds file, ACTUATOR_CONFIG carries no abort-PT thresholds.

From C4 (sequencer):

- C4-2 A script timeout fires twice (HoldTimer and ScriptRunner's deadline); into a self-transitionable state the column is re-sent, nondeterministically.
- C4-3 **An abort does not cancel a pending stage**: abort entry uses `is_transition=false`, so the previous state's +0.2 s stage lands after the abort's batch.
- C4-4 With `sequencer_owns_valves=true`, nobody commands the PWM roles during Fire.
- C4-5 controller_service: does not strip CR (`FIRE_START\r\n` → ERR); with unresolved PWM roles replies "fire gate disabled (sequencer owns the valves)" (wrong cause); can send one more test-duty PWM packet after its FIRE_STOP close; takes >3 s to exit on SIGTERM.
- C4-6 `RELOAD_CONFIG` on :9998 replies `ERR:unknown command` (daq-server/CLAUDE.md lists it as a command).

From the design notes and WP prep (2026-11-16; reported, not fixed):
- **D-OTA (lead for REPORT.md)** `POST /api/ota-flash` and `POST /api/ota-flash/flash-all` have no operator gate (`api-server.ts` A1101, A1169): behind Caddy a signed-in non-operator can reflash board firmware; `flash-all` reflashes every enabled board.
- D-CTL controller_service keeps running with no TCP fire gate when its control port fails to bind (`controller_main.cpp:147` ignores `listen()`; the control thread logs and returns).
- D-OTA2 ota_service abandons its detached client threads when SIGTERM arrives mid-flash.
- D-SL stacklight `--help` omits `--force-state`.
- D-BIND heartbeat and config_broadcast ignore `bindToDaqInterface`'s result.
- D-SEQ The sequencer's `notifyControllerFireOnce` `send()` lacks `MSG_NOSIGNAL` (harmless only because the sequencer ignores SIGPIPE).
- D-API1 `getQueryClient`/`getCalibrationStatus` are never passed in: `/api/query` and `/api/sensors` always 503, `/api/calibration_status` always the error object.
- D-API2 Malformed JSON is 500 on five routes, 400 elsewhere; `GET /api/config/profiles` can write files (`ensureSeeded()`).
- D-API3 Two paths leave a request unanswered: a throw inside a `req.on('end')` callback outside its try, an exception after `flash-all` sent SSE headers; and ~40 handlers evaluate calls after `writeHead`, so a throw there hangs the request (`ERR_HTTP_HEADERS_SENT`).
- D-WS `registerVTables(...)` on connect has no `.catch`; `conn_close`'s outbound counter skips `mission_start_time` and `session_update`; `server.ts:344-345` is a sixth copy of the `board_id % 10` slot rule.
- D-FLASH `flash/flash.sh` uses `${BLUE}` in `log_info`, never set.
- **D-SLOT (lead for REPORT.md)** A board configured in slot > 8 only warns (`Config.cpp:49-53`) and its uint8 table id wraps (`DatabaseConfig.cpp:272/371`, `(slot-1)*0x20+ch`): slot 10 lands on PT2.CH1. Stand consequence: a mistyped board_id silently corrupts or steals a live pressure channel. Related: the backend's `((n-1)%8)+1` fold; daq_bridge and calibration_service both register the calibrated tables; calibration subscribes `[0x20,0x21]` twice when the collision exists (PT2.CH1 smoothed twice).
- **D-SUB (lead for REPORT.md)** A backend subscription made while a table is being re-registered is accepted but receives 0 packets forever; the backend retries only refused subscriptions (`elodin-vtable-registry.ts` `noteSubscriptionRejected`). Stand consequence: after a startup or reconnect race a live channel can go permanently dead on the GUI with no error — rare, timing-dependent, very hard to diagnose.
- **D-HB (lead for REPORT.md, from research)** SERVER_HEARTBEAT keeps flowing while the sequencer is wedged by C4-1, so the boards' heartbeat watchdog (the independent safety layer; abort 15 s after the last heartbeat: 5 s timeout + 10 s grace) never trips while the server cannot abort. Proposal: heartbeat only while the sequencer worker is alive.
- D-EINTR A SIGTERM during an abort can fail an `AbortBroadcaster` `sendto` with EINTR (socket has `SO_SNDTIMEO`, `AbortBroadcaster.cpp:98-99,115-123`): one ABORT repeat lost. Same exposure in `ActuatorCommander` (`:354,371-379`).
- D-ERRNO Signal handlers do not save/restore `errno`. D-FORK ota calls `to_string`/`setenv` between `fork` and `exec` in a multithreaded process (`ota_service_main.cpp:218-245`).
- D-ECHO (unconfirmed) elodin-db echoes the bound table layout for each accepted subscription (`vtable_stream.rs:160-168`); `ElodinClient` drops it (`elodin-client.ts:187-203,283-289`) — the signal that would detect D-SUB.
- D-PF (suspected, unproven) `PressureFeed.cpp:118-146` re-subscribes every second any table that has delivered nothing; with a board offline it would accumulate duplicate streams. Reproduce before WP10 moves sequencer code.
- C4-3 correction: the stage lands +100 ms after the abort (golden), not +0.2 s; and the abort batch skips any role still waiting on its delay (`ActuatorCommander.cpp:492-495`) because aborts do not bump `schedule_gen_`.
- **Team proposals (from research; each changes observable behaviour):** C4-1 fix (move `publishState()` out of the locked block); abort precedence (front of queue, or broadcast ABORT from the connection thread before queueing); `cancelPendingStages()` on abort entry; single `triggerAbort`; a CLEAR_ABORT policy; staged command replies/verifiers; heartbeat-only-while-alive; fail-fast config (exit 78, `RestartPreventExitStatus=78`) for D-SLOT and friends; per-channel liveness and a D-SUB watchdog; self-pipe signal handling; `TimeoutStopSec` for the sequencer unit; Clang thread-safety annotations (compile-time only, but a header edit plus a new warning).
- D-FD (from WP8 design) after the accept loop ends, `serveTcpClients`' callers `shutdown()` fds that finished-but-unreaped clients already closed (`sequencer_main.cpp:345-349`, `controller_main.cpp:210-214`): a reused fd number can be cut, realistically a TCP socket another thread opened meanwhile.
